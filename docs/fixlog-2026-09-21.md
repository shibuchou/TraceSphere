# 修复记录（2026-09-21）：B/C 核验发现的两个问题

> 背景：合并仓库联调核验时发现「文档与实现不一致」的两个问题，当日修复并验证。
> 影响模块：platform（B）/ rca（C）。修复人：A（代改，请 B/C 复核）。

## 修复 1：platform 的 sync_runs 永远不会收尾

- **现象**：`/api/v1/health.last_sync` 永远显示 `finished_at=null, ok=0`；`sync_runs` 表只有未完成记录；但 `data/platform.log` 明确打印 `startup sync ok=True ...`。
- **根因**：`tsplatform/registry.py` 用 `db.scalar("INSERT INTO sync_runs ...")` 取行号。sqlite3 的 INSERT 不产生结果行，`fetchone()` 返回 `None` → `sync_id=None` → 收尾 UPDATE 被 `if sync_id is not None` 跳过。
- **修复**：
  - `tsplatform/db.py` 新增 `insert()`（返回 `cursor.lastrowid`）；
  - `tsplatform/registry.py` 改用 `db.insert(...)`，守卫改为 `if sync_id > 0`。
- **验证**：重启后启动同步记录 `ok=1` 且带 `finished_at/counts`；`POST /api/v1/resources/sync` 产生同样完整的记录；47 个平台单测全绿。

## 修复 2：RCA 实时诊断混入 fixture 回放数据

- **现象**：实时模式下 `diagnose --correlation-id <真实ID>` 输出为 `数据源：platform=real prometheus=real fixture=mock`，并注明"fixture 回放场景 case1-oom"；健康页 fixture 恒为 `mock`。
- **根因**：`engine.Gather` 第一步只判断 `e.fixtures != nil`（fixtures 目录总会被加载），未判断 `cfg.Sources.Fixture.Enabled`，与 `engine.New` 注释意图及 `docs/API.md` §6 的「real → degraded → fixture 降级优先级」不符，导致回放证据无条件混入真实诊断。
- **修复**：
  - `engine.go`：fixture 基线仅在 `Fixture.Enabled`（`--fixture` / `TRACESPHERE_RCA_FIXTURE`）时并入；新增 `mergeFixtureBaseline()` 公共路径；
  - 新增 3.5 降级后备：`platform != real` 时按 API.md §6 自动并入 fixture（platform 不可用 → prometheus + fixture；全不可用 → 仅 fixture），并在 `notes` 明示；
  - `views.go`：健康页 fixture 状态改为：显式回放或真实源不可用 → `mock`，实时模式 → `off`（场景列表仍展示）。
- **验证**：
  - 实时诊断：`platform=real prometheus=real fixture=off`，无回放说明；
  - 健康页：`fixture=off` + `fixture_scenarios` 仍在；
  - 显式回放 `diagnose --scenario case1-oom` 不受影响（`platform=mock prometheus=mock fixture=mock`）；
  - `go test ./...` 全绿。
