# TraceSphere 方案说明

> 面向 ZSvirt 虚拟机内容器与智能体工作负载的全栈可观测平台（智算云赛道 · ZSvirt 赛题）
> 本文对应交付要求 §3.a：总体架构 / 部署边界 / 数据模型 / 采集方式 / 资源关联逻辑 / 告警策略 / 事件关联与诊断流程 / ZSvirt 集成点与权限安全设计。

---

## 1. 设计目标

以「**虚拟机为边界、工作负载为对象、事件关联为核心**」，统一组织指标、日志、事件与告警证据，回答：
**某个 Agent 任务的一次失败，究竟由应用、容器、虚拟机、GPU 还是宿主机引起？**

三条硬约束：

1. **可解释**：诊断输出根因候选 + 影响范围 + 逐条证据 ID，评分是"证据命中评分"，不是概率；
2. **低侵入**：VM 内单二进制探针 + systemd，采集失败自动降级，可一键卸载；
3. **可复现**：真实演练数据可落盘为 fixture 回放；无 GPU / 无 eBPF 环境有明确降级路径。

## 2. 总体架构

```text
┌─────────────────────────── ZSvirt 基础设施层 ────────────────────────────┐
│  RESTProvider（真实，只读同步）  /  FixtureProvider（回放与降级）          │
│  资源清单：Host / VM / Cluster / Zone / Network / Storage / Image        │
│  告警清单：zwatch/alarms、zwatch/events → Schema v1 alert 事件           │
└──────────────────────────────────┬───────────────────────────────────────┘
                                   ▼
┌────────────────────────── Platform（成员 B）─────────────────────────────┐
│ Resource Registry + Resource Graph（资源图，SQLite WAL）                  │
│ Event Ingest（Schema v1 归一化 + 身份补全 + 短 ID 前缀归一）              │
│ Correlation Engine（应用锚点 + 同资源时间窗，产"关联簇 = 告警"）          │
│ Evidence Store（证据链：信号 / 值 / 来源事件 / 时间）                     │
│ HTTP API /api/v1（resources / events / evidence / clusters / context …） │
└───────────────┬────────────────────────────────┬─────────────────────────┘
                │                                │
    ┌───────────▼───────────┐        ┌───────────▼───────────────────────────┐
    │ RCA 诊断（成员 C）     │        │ VM 内采集与负载（成员 A）             │
    │ YAML 规则 + Evidence   │        │ vm-agent：eBPF + PSI + cgroup + 内核  │
    │ Match 五维评分（0-100）│        │ agent-service：AppEvent 直报           │
    │ CLI + HTTP + Console   │        │ llama.cpp / tool-service / Toxiproxy  │
    └───────────┬───────────┘        │ Prometheus + cAdvisor + Mock DCGM     │
                │                    └───────────────────────────────────────┘
    ┌───────────▼───────────┐
    │ Web Console（React）   │  拓扑 / 健康 / 告警 / 诊断 四视图
    └───────────────────────┘
```

平台与诊断的边界：RCA 只读平台 API（`/context` 聚合输入），不自建采集、不自建关联；
平台不做规则逻辑。新增诊断规则 = 新增 YAML，引擎代码不变。

## 3. 部署边界与最小环境

| 组件 | 部署位置 | 说明 |
|---|---|---|
| platform（Python 3.10+，零第三方依赖） | 宿主机或管理节点（systemd `tracesphere-platform`，端口 8000） | 只读同步 ZSvirt + 事件入库 + 关联 |
| RCA + Console（Go 1.22+ / 静态构建） | 同上（systemd `tracesphere-rca`，端口 8010） | 规则诊断 + 托管前端 |
| vm-agent（Go 单二进制） | 业务 VM（systemd `tracesphere-vm-agent`） | eBPF / PSI / cgroup / OOM 日志 |
| 样例负载（Docker Compose） | 业务 VM | llama.cpp + agent-service + tool-service + Toxiproxy + Prometheus + cAdvisor (+ mock-dcgm) |

最小环境：Linux x86_64 KVM 宿主机 + 一台 ZSvirt 管理的业务 VM（4 vCPU / 4 GiB 起）；
无 GPU：Mock DCGM 提供模拟显存信号；无 eBPF：探针降级为 PSI/cgroup/日志采集。

## 4. 数据模型

### 4.1 Schema v1 事件（冻结）

`schema_version / origin / mode / observed_at / ingested_at / type / event_type /
resource_id / correlation_id / trace_id / task_id / severity / source / cluster_id / payload`

兼容三种入库格式：AppEvent（应用直报）/ Schema v1 完整事件 / 松散事件（探针指标行）。
`origin ∈ {zsvirt, ebpf, cgroup, cadvisor, app, fluentbit, gpu}`，`mode ∈ {real, mock}`。

### 4.2 资源模型与关系词表

资源 ID 规范 `<kind>:<key>`：
`host: / vm: / container: / process: / service: / task: / gpu: / cluster: / zone: / network: / datastore: / volume: / image: / offering:`

关系词表（`GET /api/v1/meta` 可查）：
`contains / assigned_to / attached_to / uses / has_volume / over / provides / runs_on / calls / spawns`

典型链路：`host -contains-> vm -contains-> container -runs_on-> service -runs_on-> task`；
`gpu -assigned_to-> vm`（Mock DCGM 降级模式下同样成立）。

### 4.3 证据模型（Evidence Item）

`evidence_id / signal / kind / layer / resource_id / observed_at / severity / value / unit /
description / source_event_ids / payload`

- `signal` 为归一化信号名（如 `memory.events.oom_kill`、`psi_cpu_some_avg10`、`gpu.memory_used_ratio`、`tool.result`、`task.failed`）；
- 计数型信号窗口内做增量合并（Δ>0 才成证据），指标型取窗口峰值；噪声信号（如原始采样行）不入证据链；
- 每条证据保留 `source_event_ids` 原始事件引用，支持逐条溯源。

## 5. 采集方式

| 信号 | 采集者 | 路径 | 频率 |
|---|---|---|---|
| ZSvirt 资源 / 告警 | platform | REST 只读同步（登录 + inventory），启动 + 可配置周期（`ZSVIRT_SYNC_INTERVAL` 秒） | 启动 + 120s |
| 容器 cgroup（内存/CPU/限流） | vm-agent | cgroup v2 直读（逐容器） | 15s 直报 |
| PSI（CPU/内存/IO 压力） | vm-agent | `/proc/pressure/*` | 5s 直报 |
| 进程 exec/exit、网络重传 | vm-agent | eBPF（tracepoint/kprobe，失败降级） | 实时 |
| 内核 OOM | vm-agent | journal 模式匹配 → 结构化事件 | 10s 轮询 |
| Agent 任务 / 工具 / 推理 | agent-service | AppEvent 直报（含 `correlation_id` / `task_id`） | 实时 |
| 容器指标（Prometheus 侧） | cAdvisor | Prometheus 抓取 → RCA 适配 | 5s |
| GPU 显存（降级） | mock-dcgm | 模拟 DCGM 指标：直报 + `/metrics` 暴露 | 15s |

所有 VM 内事件直报平台 `/api/v1/events`（无桥接进程）；探针开销实测见 `docs/evidence/`。

## 6. 资源关联逻辑

1. **资源同步映射**：ZSvirt inventory → 领域模型（Host / VM / Cluster / Zone / Network / Volume / Image / Alarm），保留 `origin/mode`（real/mock）与 labels；
2. **身份补全（ingest）**：容器事件按 12 位短 ID **前缀归一**到 64 位容器 ID；
   `VM --contains--> Container` 边由事件中的 `vm_uuid` 建立；
3. **应用层归因优先**：同时携带容器/服务/任务的 AppEvent 挂到最具体实体（container > service > task > vm），避免任务证据上卷污染；
4. **GPU 层**：`Host --contains--> GPU --assigned_to--> VM`（真实环境可由 ZSvirt GPU 清单或 DCGM exporter 接入；降级模式由 `mock_gpu` 配置注册）；
5. **关联键**：`resource_id` 为主键，`correlation_id` / `task_id` 连接应用层；跨层追溯依靠资源图（RCA 影响范围按 depth 计算）。
6. **eBPF 事件身份**：vm-agent 按 PID 解析 `/proc/<pid>/cgroup` 得到容器 ID（60s 缓存）并附 `vm_uuid`，使内核事件（OOM/重传/进程）落到具体容器资源，而非孤立事件。
7. **扩展点（Roadmap）**：进程层默认仅本地日志（`VMAGENT_REPORT_PROCESS=1` 开启入图以免拓扑噪声）；租户/项目维度待 ZSvirt 侧提供租户字段后按 labels 映射，不影响现有四层关联。

## 7. 事件关联与诊断流程

```text
事件入库 ──► 关联引擎（两遍）
              ├─ pass1：correlation_id 锚（Agent 任务链路：task/tool/inference/容器/内核证据）
              └─ pass2：同资源时间窗锚（无 corr 的系统层事件聚合）
                        │
                        ▼
                关联簇 cluster（= 一条告警）──► Evidence 生成（signal/value/delta/unit）
                        │
                        ▼
        RCA：加载 rules/*.yaml ──► 证据匹配（mandatory/optional/阈值/时序 after）
                        │
                        ▼
        Evidence Match 五维评分（0–100）：
        rule_match 55 + temporal_precedence 15 + resource_adjacency 10
        + signal_strength 10 + independent_evidence 10
                        │
                        ▼
        输出：Top-N 根因候选 + 影响范围（资源图 depth）+ 处置建议（依据/操作/风险）
                证据 ID 全量可溯源；时间线按 应用 / 容器 / 虚拟机 / 云平台 分层着色
```

无证据不诊断（空证据 → 0 条结论），避免"if/else 硬编码"式输出。

## 8. 告警策略

- **分级**：severity ∈ info / warning / major / critical（规则 YAML 声明 + 证据严重度取最大）；
- **聚合**：同一关联簇合并为一条告警（incident），展示证据条数、影响任务数与 Top-1 评分；
- **去重**：事件入库带 `dedup_key`，重复事件不重复计分；
- **阈值/基线**：阈值与基线差写入规则 YAML（如 PSI > 5%、显存占用 > 90%），环境变更时改规则即可；
- **运营状态**：open → acknowledged（确认）→ resolved（已处理），支持 silenced（静默）/恢复，
  状态由 RCA `POST /api/v1/incidents/{id}/status` 持久化（JSON 文件），Console 一键操作；
- **边界**：不重复自研 Alertmanager 的 grouping/silence/inhibition/dedup，生产环境可对接 Alertmanager 做通知渠道，平台只负责证据化告警。

## 9. 与 ZSvirt 集成点及权限 / 安全设计

| 项 | 设计 |
|---|---|
| 集成接口 | `accounts/login`（sha512 密码）+ 只读 inventory 查询（hosts / vm-instances / zwatch alarms 等，路径可配置） |
| 权限 | 单个只读账号；不调用写接口；不修改任何 ZSvirt 资源 |
| 凭据 | `ZSVIRT_PASSWORD` 环境变量（`/etc/tracesphere/platform.env`，600），不进仓库与日志 |
| 访问控制 | 平台 API `TRACESPHERE_API_TOKEN`（非回环绑定未配置即拒绝启动，直报/注册链路带 Bearer）；RCA `TRACESPHERE_RCA_TOKEN`；两边写接口每 IP 分钟级限流（默认 600）；工作负载控制面仅回环绑定（Prometheus 跨机读取用 `PROM_BIND`） |
| 失败处理 | 401/403 自动重登；登录失败/网络异常时保持已有数据并标记 `degraded`（health 可见） |
| 数据面安全 | ingest 字段白名单；不上传问题/回答等业务文本（仅长度等元数据）；内核日志仅做 OOM 模式匹配；平台 API 支持静态令牌 |
| 提交脱敏 | `tools/sanitize-for-submission.sh`（排除内部资料 + 内网信息替换 + 残留扫描；含 `docs/evidence` 公开副本） |

## 10. 降级与可复现

- **fixture 回放**：`tracesphere diagnose --scenario <case>`、`TRACESPHERE_RCA_FIXTURE=1` 启动 Console 整体回放；fixture 由真实演练 `capture` 落盘，回放结果与现场一致（Top-1 + 评分）；
- **无 GPU**：Mock DCGM（`TRACESPHERE_MOCK_GPU=1` + `mock-dcgm` 容器），Case 4 可复现；
- **无 eBPF**：探针自动降级到 PSI / cgroup / journal；
- **一键验收**：`tools/acceptance.sh` 依次完成四场景注入 → 采集 → 关联 → 诊断 → fixture 回写。
