### 1.3 约定

- 文中 `<...>` 均为占位符，部署时替换为实际值。
- 所有口令、Token、内网地址只写入 `/etc/tracesphere/*.env` 或部署方环境变量，不写入仓库、不写入命令历史。

## 2. 部署架构

### 2.1 逻辑拓扑

![TraceSphere 分层架构](diagrams/architecture-layers.svg)

```text
┌────────────────────────────────────────────────────────────────────┐
│ ZSvirt 管理节点（<MN_IP>）                                          │
│  UI 443 ｜ REST API 8080（/zstack/v1）                             │
│  Zone / Cluster / Host / Storage / L2-L3 Network / Image / Offering│
└──────────────────────────────┬─────────────────────────────────────┘
                               │ 只读 inventory + zwatch 查询
┌──────────────────────────────▼─────────────────────────────────────┐
│ 平台节点（<PLATFORM_IP>，可与 KVM 宿主机同机）                       │
│  platform  :8000  资源图 / 事件 / 证据 / 关联                       │
│  rca       :8010  规则诊断 + Console 静态托管                       │
│  console/dist     React 构建产物                                    │
└──────────────────────────────┬─────────────────────────────────────┘
                               │ 事件直报 / 指标读取 / 页面访问
┌──────────────────────────────▼─────────────────────────────────────┐
│ 业务 VM（<VM_IP>，ZSvirt 管理）                                     │
│  vm-agent（eBPF + PSI + cgroup + journal，systemd）                 │
│  Docker Compose：agent-service / tool-service / llama-server       │
│  Toxiproxy / Prometheus / cAdvisor / mock-dcgm                     │
└────────────────────────────────────────────────────────────────────┘
```

### 2.2 组件职责

| 组件 | 部署位置 | 运行形态 | 职责 |
|---|---|---|---|
| `platform` | 平台节点 | systemd `tracesphere-platform`，端口 8000 | ZSvirt 只读同步、资源图、事件入库、证据与关联簇 |
| `rca` | 平台节点 | systemd `tracesphere-rca`，端口 8010 | YAML 规则匹配、Evidence Match 评分、诊断 API、Console 托管 |
| `console` | 平台节点 | 静态文件，由 RCA 托管 | 拓扑 / 健康 / 告警 / 诊断四个页面 |
| `vm-agent` | 业务 VM | systemd `tracesphere-vm-agent` | 内核事件、PSI、cgroup、OOM 日志采集与直报 |
| `workload` | 业务 VM | Docker Compose | 可复现的 Agent 业务链路与故障注入 |
| `mock-dcgm` | 业务 VM | 容器 | 无 GPU 环境的模拟显存指标源 |

### 2.3 数据流

1. platform 启动时登录 ZSvirt，拉取 host / VM / cluster / zone / network / storage / image / offering / alarm 等清单，生成资源与边；
2. 业务 VM 内 vm-agent 与 agent-service 通过 `POST /api/v1/events` 直报事件；
3. RCA 通过 `GET /api/v1/context`、`/clusters`、`/events` 读取平台上下文，同时从 Prometheus 读取容器指标；
4. RCA 执行规则匹配，输出根因候选、证据 ID、影响范围与处置建议；
5. Console 通过同源 `/api/v1` 调用 RCA，页面展示拓扑、健康、告警与诊断。

## 3. 环境要求

### 3.1 硬件

| 项 | 最低 | 实测环境 |
|---|---|---|
| 宿主机 | Linux x86_64，8 vCPU / 16 GiB / 100 GiB 可用磁盘 | 20 vCPU / 30 GiB / 176 GiB |
| 虚拟化 | KVM + 嵌套虚拟化（`kvm_intel.nested=1`） | 是 |
| ZSvirt 管理节点 VM | 8 vCPU / 8 GiB | 12 vCPU / 16 GiB |
| 业务 VM | 4 vCPU / 4 GiB / 40 GiB | 4 vCPU / 4 GiB / 40 GiB |
| GPU | 可选；无 GPU 用 Mock DCGM 降级 | 无 GPU |

### 3.2 软件

| 软件 | 版本 | 用途 |
|---|---|---|
| ZSvirt | v1.0.0（x86_64 qcow2） | 虚拟化管理平台 |
| libvirt / qemu-kvm / virt-install | 发行版自带 | 启动 ZSvirt 管理节点 |
| Ubuntu | 24.04 LTS | 业务 VM |
| Docker Engine + Compose v2 | 24+ / v2 | 样例负载 |
| Python | 3.10+（平台零第三方依赖） | platform |
| Go | 1.22+（RCA） / 1.25+（vm-agent） | 构建诊断服务与探针 |
| Node.js | 22 | 构建 Console |
| clang / bpftool / BTF | 内核 6.8+ 提供 `/sys/kernel/btf/vmlinux` | vm-agent eBPF |
| SQLite | 3.x（Python 内置） | 平台本地存储 |
| Prometheus / cAdvisor / Toxiproxy / llama.cpp | 见 Compose 镜像 digest | 样例负载 |

### 3.3 网络与端口

| 节点 | 端口 | 默认绑定 | 说明 |
|---|---|---|---|
| ZSvirt 管理节点 | 443 | UI | 浏览器初始化，不代理 `/zstack` |
| ZSvirt 管理节点 | 8080 | REST API | platform 通过 `http://<MN_IP>:8080/zstack/v1` 访问 |
| 平台节点 | 8000 | `0.0.0.0`（生产） | platform API；非回环绑定必须配置 Token |
| 平台节点 | 8010 | `:8010` | RCA API + Console |
| 业务 VM | 22 | SSH | 部署与运维 |
| 业务 VM | 9090 | `PROM_BIND`，默认回环 | Prometheus；跨机读取时绑定 VM IP |
| 业务 VM | 8080 | `BIND_ADDR`，默认回环 | cAdvisor |
| 业务 VM | 8081 | `BIND_ADDR`，默认回环 | llama-server |
| 业务 VM | 8082 | `BIND_ADDR`，默认回环 | agent-service `/task` |
| 业务 VM | 8474 / 8666 | `BIND_ADDR`，默认回环 | Toxiproxy 控制面 / 工具代理 |
| 业务 VM | 9400 | `BIND_ADDR`，默认回环 | mock-dcgm `/metrics` 与 `/inject` |
| 业务 VM | 9000 | 容器内网 | tool-service，不发布到宿主机 |

### 3.4 时间与时钟

- 所有节点启用 NTP / chrony；
- platform 与 ZSvirt 的时钟偏差建议 < 1 秒，关联窗口默认 5 秒；
- 业务 VM 与平台节点偏差同样应 < 5 秒，否则应用事件与系统事件无法归入同一关联簇；
- 检查命令：

```bash
timedatectl status
chronyc tracking 2>/dev/null || ntpq -p 2>/dev/null || true
```

## 4. 部署前准备

### 4.1 规划表

部署前填写下表，后续命令直接引用：

| 变量 | 示例 | 说明 |
|---|---|---|
| `MN_IP` | `192.0.2.10` | ZSvirt 管理节点 IP |
| `PLATFORM_IP` | `192.0.2.20` | 平台节点 IP（业务 VM 可达） |
| `VM_IP` | `<VM_IP>` | 业务 VM IP |
| `VM_UUID` | `<ZSvirt VM uuid>` | 业务 VM 在 ZSvirt 中的 UUID |
| `ZSVIRT_PASSWORD` | `<ZSvirt admin 密码>` | 只写入环境变量 |
| `API_TOKEN` | `openssl rand -hex 24` 生成 | platform 静态 Token |
| `RCA_TOKEN` | `openssl rand -hex 24` 生成 | RCA 静态 Token（可选但推荐） |
| `VM_PASSWORD` | `<ubuntu 用户密码>` | 仅部署脚本使用 |

### 4.2 宿主机检查

```bash
# 嵌套虚拟化
egrep -c '(vmx|svm)' /proc/cpuinfo
cat /sys/module/kvm_intel/parameters/nested 2>/dev/null || true
ls -l /dev/kvm

# libvirt
virsh list --all
virsh net-list --all
```

### 4.3 业务 VM 内核检查（vm-agent 前置）

```bash
uname -r
test -f /sys/kernel/btf/vmlinux && echo "BTF OK"
mount | grep tracefs || echo "tracefs not mounted"
cat /proc/pressure/cpu >/dev/null && echo "PSI OK"
stat -fc %T /sys/fs/cgroup   # 期望 cgroup2fs
```

eBPF 需要 root 或 `CAP_BPF + CAP_PERFMON`；tracepoint 依赖 tracefs。任一条件不满足时 vm-agent 会自动降级为 PSI/cgroup 采集，不阻塞部署。

### 4.4 目录规划

全量部署推荐统一放在 `/opt/tracesphere`，因为样例负载的 Compose 文件使用绝对路径挂载：

```text
/opt/tracesphere/
├── platform/                 # 平台代码与 data/tracesphere.db
├── rca/                      # 诊断服务与 rules/ fixtures/
├── console/                  # 前端源码与 dist/
├── vm-agent/                 # 探针源码与 bin/vm-agent
├── workload/                 # 样例负载（Compose、故障脚本）
├── models/model.gguf         # 样例模型（不入仓库）
├── deploy/                   # 部署脚本与 systemd 单元
└── tools/                    # demo-up / acceptance / reset-platform
```

```bash
sudo install -d -o "$USER" -g "$USER" /opt/tracesphere
sudo install -d -o "$USER" -g "$USER" /opt/tracesphere/models
sudo install -d /etc/tracesphere
```

> `tools/acceptance.sh` 当前假设仓库位于 `$HOME/tracesphere`，并且负载位于 `/opt/tracesphere/workload`。若部署在 `/opt/tracesphere`，请把脚本中的 `cd "$HOME/tracesphere/rca"` 改为实际路径，或把仓库放到 `$HOME/tracesphere` 后建立 `/opt/tracesphere` 软链接。

### 4.5 生成 Token

```bash
openssl rand -hex 24        # API_TOKEN
openssl rand -hex 24        # RCA_TOKEN
```

Token 只保存到 `/etc/tracesphere/platform.env` 与 `/etc/tracesphere/rca.env`，权限 600。

## 5. ZSvirt 管理节点与业务 VM

> 本节给出通用步骤，并标注本仓库实测环境中的已知问题与兜底方案。不同 ZSvirt 版本的 UI 文案可能不同，以实际界面为准。

### 5.1 获取并校验 ZSvirt 镜像

从官方发布渠道获取 ZSvirt v1.0.0 x86_64 qcow2。仓库内 `deploy/zsvirt-deploy.sh` 内置镜像文件名与 SHA256 校验逻辑，可按实际文件名修改脚本头部变量。

```bash
sha256sum ZSvirt-x86_64-1.0.0-h84r.qcow2
```

### 5.2 创建管理节点 VM

脚本方式：

```bash
bash deploy/zsvirt-deploy.sh --memory 16384 --vcpus 12 --vm-name zsvirt-mgmt
```

等价的手工命令：

```bash
sudo virsh net-start default || true
sudo virsh net-autostart default || true
sudo virt-install \
  --name zsvirt-mgmt \
  --memory 16384 --vcpus 12 \
  --cpu host-passthrough \
  --disk path=/var/lib/libvirt/images/ZSvirt-x86_64-1.0.0-h84r.qcow2,format=qcow2,bus=virtio \
  --import \
  --network network=default,model=virtio \
  --graphics none \
  --osinfo detect=on,require=off \
  --noautoconsole
```

观察 DHCP 地址：

```bash
sudo virsh net-dhcp-leases default
```

### 5.3 首次登录与控制台

```bash
sudo virsh console zsvirt-mgmt
```

首次登录后：

1. 按官方文档获取初始密码并立即修改；
2. 启用管理网卡并获取地址：

```bash
ip link set <mgmt-nic> up
dhclient <mgmt-nic>
ip addr show <mgmt-nic>
```

3. 设置管理服务地址并启动：

```bash
sudo zstack-ctl change_ip --ip <MN_IP>
sudo zstack-ctl start
```

4. 浏览器访问 `https://<MN_IP>` 完成初始化。

### 5.4 平台资源初始化

在 ZSvirt UI 中依次创建：

| 资源 | 建议值 | 说明 |
|---|---|---|
| 数据中心 / Zone | `Datacenter-1` | 默认即可 |
| 集群 / Cluster | `Cluster-1`（KVM） | 挂载本地存储 |
| 物理机 / Host | 管理节点自身或独立 KVM 主机 | 状态必须 `Connected` |
| 主存储 | 本地目录存储 | **必须显式挂载到集群**，否则调度器报 `No available host found` |
| 镜像存储 | 本地镜像存储 | 挂载到数据中心 |
| 二层网络 / 分布式交换机 | Linux Bridge | 绑定物理网卡 |
| 三层网络 / 端口组 | VLAN 按环境规划 | 启用 IPAM、DHCP、Userdata |
| IP 段 | 与宿主机同网段 | 网关、DNS 按环境填写 |
| 系统镜像 | Ubuntu 24.04 cloud image | 建议 qcow2 |
| 实例规格 | `4 vCPU / 4 GiB` | 供业务 VM 使用 |

### 5.5 验证 ZSvirt REST API

```bash
# 口径：密码字段传 sha512(明文) 的 hex，不是明文
HASH=$(printf '%s' "$ZSVIRT_PASSWORD" | sha512sum | awk '{print $1}')

curl -s -X PUT "http://<MN_IP>:8080/zstack/v1/accounts/login" \
  -H 'Content-Type: application/json' \
  -d "{\"logInByAccount\":{\"accountName\":\"admin\",\"password\":\"$HASH\"}}"

# 从响应中取 sessionId，后续请求带：
# Authorization: OAuth <sessionId>
curl -s -H "Authorization: OAuth <sessionId>" \
  "http://<MN_IP>:8080/zstack/v1/vm-instances"
```

必须遵守的接口约定：

| 项 | 约定 |
|---|---|
| API 入口 | `http://<MN_IP>:8080/zstack/v1`；443 是 UI 的 nginx，只代理 `/download-helper`，不代理 `/zstack` |
| 登录请求体 | `{"logInByAccount":{"accountName":"admin","password":"<sha512>"}}` |
| 认证头 | `Authorization: OAuth <session-uuid>` |
| 会话过期 | 401/403 或错误码含 `SESSION/AUTH`，platform 会自动重登一次 |
| 初始密码 | 出厂密码不是 `password`；可用 `zstack-ctl reset_password --password '<new>'` 重置，随后 `zstack-ctl restart_node` 生效 |
| 管理网卡 | guest 内默认 DOWN，需要 `ip link set <mgmt-nic> up` + DHCP |

### 5.6 创建业务 VM

在 ZSvirt UI 或 API 中创建：

| 项 | 值 |
|---|---|
| 名称 | `workload-vm` |
| 规格 | 4 vCPU / 4 GiB |
| 系统盘 | 40 GiB |
| 镜像 | Ubuntu 24.04 cloud image |
| 网络 | 业务端口组（与平台节点路由可达） |
| 用户数据 | 注入 SSH 公钥或初始密码 |

记录 VM UUID，后续写入 `TRACESPHERE_VM_UUID` / `VMAGENT_VM_UUID` / `TRACESPHERE_MOCK_GPU_VM`。

### 5.7 网络与 cloud-init 兜底（实测环境）

以下问题在 ZSvirt v1.0.0 实测环境中出现过，按需使用：

1. **flat DHCP 未下发**：VM 网卡已接入网桥但未获取 IP。兜底方案是在管理节点网桥上启动 dnsmasq 并做 NAT：

```bash
# 示例：网桥 <WORKLOAD_BRIDGE>，地址段 <VM_SUBNET>
sudo ip addr add <BRIDGE_IP>/24 dev <WORKLOAD_BRIDGE>
sudo dnsmasq --interface=<WORKLOAD_BRIDGE> --bind-interfaces \
  --dhcp-range=<DHCP_START>,<DHCP_END>,255.255.255.0,12h \
  --dhcp-option=3,<GATEWAY> --dhcp-option=6,<DNS>
sudo iptables -t nat -A POSTROUTING -s <VM_SUBNET> ! -d <VM_SUBNET> -j MASQUERADE
```

2. **cloud-init 未生成 config drive**：制作 NoCloud seed ISO 挂载为 cdrom，注入 `ubuntu` / `root` 密码；生产环境优先使用 SSH 公钥。
3. **根盘扩容 API 不可用**：离线 `qemu-img resize` 到 40G，更新 `VolumeVO.size`，VM 内 `growpart` + `resize2fs`。
4. **跨网段访问**：在平台节点或跳板机添加 `<VM_SUBNET> via <MN_IP>` 路由，保证平台节点能访问 VM 的 9090 与 SSH。

> 这些兜底方案只针对特定 ZSvirt 构建；如果目标环境 DHCP、cloud-init、卷扩容正常，直接使用官方能力即可。

## 6. 平台侧部署（platform + RCA + Console）

### 6.1 获取代码

```bash
sudo mkdir -p /opt/tracesphere
sudo chown "$USER":"$USER" /opt/tracesphere
git clone <仓库地址> /opt/tracesphere
cd /opt/tracesphere
```

如使用提交包，把 `03-源码-tracesphere/` 中的内容解压到 `/opt/tracesphere`（不要把外层目录一起放进去）。

### 6.2 platform 配置

```bash
cd /opt/tracesphere
cp platform/config/platform.example.json platform/config/platform.json
mkdir -p platform/data rca/data
```

编辑 `platform/config/platform.json`，最小改动：

```json
{
  "platform": {
    "host": "0.0.0.0",
    "port": 8000,
    "db_path": "data/tracesphere.db",
    "log_level": "INFO"
  },
  "zsvirt": {
    "provider": "rest",
    "base_url": "http://<MN_IP>:8080/zstack/v1",
    "account": "admin",
    "password_env": "ZSVIRT_PASSWORD",
    "sync_on_start": true,
    "sync_interval_sec": 120,
    "verify_tls": false
  },
  "api": {
    "token": "",
    "cors_origins": ["*"],
    "max_body_bytes": 5242880,
    "rate_limit_per_min": 600
  },
  "correlation": {
    "window_seconds": 5.0,
    "max_events": 5000
  },
  "mock_gpu": {
    "enabled": false
  }
}
```

> `api.token` 留空也可以，但必须通过环境变量 `TRACESPHERE_API_TOKEN` 注入；**非回环绑定且没有 Token 时 platform 会拒绝启动（退出码 3）**。

无 GPU、需要 Case 4 时改为：

```json
"mock_gpu": {
  "enabled": true,
  "uuid": "mock-gpu0",
  "name": "Mock GPU 0 (DCGM)",
  "vendor": "NVIDIA (Mock)",
  "memory_total_bytes": 8589934592,
  "vm_uuid": "<VM_UUID>"
}
```

也可以只用环境变量开启：

```bash
TRACESPHERE_MOCK_GPU=1
TRACESPHERE_MOCK_GPU_UUID=mock-gpu0
TRACESPHERE_MOCK_GPU_VM=<VM_UUID>
```

### 6.3 写入环境文件

```bash
sudo tee /etc/tracesphere/platform.env >/dev/null <<'EOF'
ZSVIRT_PASSWORD=<ZSVIRT admin 密码>
ZSVIRT_BASE_URL=http://<MN_IP>:8080/zstack/v1
TRACESPHERE_API_TOKEN=<API_TOKEN>
TRACESPHERE_RATE_LIMIT=600
ZSVIRT_SYNC_INTERVAL=120
# 无 GPU 时启用：
# TRACESPHERE_MOCK_GPU=1
# TRACESPHERE_MOCK_GPU_UUID=mock-gpu0
# TRACESPHERE_MOCK_GPU_VM=<VM_UUID>
EOF
sudo chmod 600 /etc/tracesphere/platform.env
```

### 6.4 构建 RCA 与 Console

```bash
cd /opt/tracesphere/rca
go build -o bin/tracesphere ./cmd/tracesphere

cd /opt/tracesphere/console
npm ci
npm run build          # 产出 console/dist/
```

构建环境要求：

- RCA 需要 Go 1.22+，可访问 `gopkg.in/yaml.v3`；
- Console 需要 Node 22，`npm ci` 使用 `package-lock.json`；
- 若网络受限，可先配置 npm / Go 代理，再执行构建；
- `npm run build` 会先执行 `tsc --noEmit`，类型错误会阻断构建。

### 6.5 写入 RCA 环境文件

```bash
sudo tee /etc/tracesphere/rca.env >/dev/null <<'EOF'
TRACESPHERE_PROMETHEUS_URL=http://<VM_IP>:9090
TRACESPHERE_PLATFORM_URL=http://127.0.0.1:8000
TRACESPHERE_PLATFORM_TOKEN=<API_TOKEN>
TRACESPHERE_RCA_TOKEN=<RCA_TOKEN>
TRACESPHERE_RCA_RATE_LIMIT=600
EOF
sudo chmod 600 /etc/tracesphere/rca.env
```

说明：

- `TRACESPHERE_PLATFORM_TOKEN` 必须与 platform 的 `TRACESPHERE_API_TOKEN` 一致，否则 RCA 读不到平台数据；
- `TRACESPHERE_RCA_TOKEN` 为空时 Console 无需 Token；生产环境建议设置；
- `TRACESPHERE_PROMETHEUS_URL` 指向业务 VM 的 9090，对应业务 VM 侧 `PROM_BIND=<VM_IP>`。

### 6.6 安装并启动 systemd 服务

```bash
cd /opt/tracesphere
sudo bash deploy/systemd/install-services.sh
```

脚本会：

1. 停止可能存在的 nohup 版 platform / rca；
2. 用当前 `SUDO_USER` 和仓库绝对路径替换单元文件中的 `__TS_USER__` / `__TS_ROOT__`；
3. 生成 `/etc/tracesphere/platform.env`、`/etc/tracesphere/rca.env` 模板（已存在则保留）；
4. `systemctl enable --now tracesphere-platform tracesphere-rca`。

检查：

```bash
systemctl status tracesphere-platform --no-pager
systemctl status tracesphere-rca --no-pager
journalctl -u tracesphere-platform -n 50 --no-pager
journalctl -u tracesphere-rca -n 50 --no-pager
```

> 单元文件以 `SUDO_USER` 运行。若仓库位于 `/opt/tracesphere` 且属主是 `ubuntu`，请用 `sudo -E bash ...` 或确保 `sudo` 保留了正确的 `SUDO_USER`；同时保证该用户对 `platform/data`、`rca/data`、`console/dist` 有读写权限。

### 6.7 Console 构建模式

Console 的数据源模式是**构建期**变量，运行时只读：

| 模式 | 构建命令 | 行为 |
|---|---|---|
| api（默认） | `npm run build` | 请求同源 `/api/v1`，由 RCA 托管 |
| fixture | `VITE_DATA_SOURCE=fixture npm run build` | 读取 `src/mocks/*.json`，无需后端 |

常用变量：

```bash
VITE_DATA_SOURCE=api
VITE_RCA_BASE_URL=                 # 留空 = 同源 /api/v1
VITE_PLATFORM_BASE_URL=http://<PLATFORM_IP>:8000
VITE_DEFAULT_SCENARIO=case1-oom
VITE_ENV_LABEL="ZSvirt 智算云 · 演示环境"
```

生产部署推荐 `VITE_RCA_BASE_URL` 留空，由 RCA 在 8010 端口同时提供 API 与静态页面，避免 CORS。

### 6.8 访问与鉴权

- Console：`http://<PLATFORM_IP>:8010/`
- 若设置了 `TRACESPHERE_RCA_TOKEN`，第一次访问使用：

```text
http://<PLATFORM_IP>:8010/?token=<RCA_TOKEN>
```

页面会把 Token 写入浏览器 `localStorage` 的 `tracesphere.auth_token`，后续请求自动带 `Authorization: Bearer`。Token 会留在地址栏，演示前建议重新打开不带 `?token=` 的地址。

### 7.3 配置 Compose 环境

```bash
cd /opt/tracesphere/workload
cp .env.example .env
```

编辑 `.env`：

```bash
PLATFORM_EVENTS_URL=http://<PLATFORM_IP>:8000/api/v1/events

# TASK_TOKEN=<TASK_TOKEN>

```

注意：

- `PLATFORM_EVENTS_URL` 是**完整事件端点**，必须带 `/api/v1/events`；
- `PROM_BIND` 必须设置为业务 VM 的 IP（或 `0.0.0.0` + 防火墙限制），否则平台节点上的 RCA 无法读取 9090；
- `BIND_ADDR=127.0.0.1` 使 cAdvisor / llama / Toxiproxy / mock-dcgm / agent-service 只绑回环；
- `PLATFORM_TOKEN` 与平台 `TRACESPHERE_API_TOKEN` 一致，否则直报 401；
- mock-dcgm 仅在无 GPU 降级模式下使用，真实 GPU 环境可移除该服务或忽略。

### 7.4 启动负载

### 7.5 构建并安装 vm-agent

在业务 VM 上构建（需要 Go 1.25+、clang、bpftool、BTF）：

```bash

sudo bash deploy/install.sh bin/vm-agent
```

安装脚本会：

- 安装二进制到 `/opt/tracesphere/bin/vm-agent`；
- 生成 `/etc/tracesphere/agent.env` 模板（已存在则保留）；
- 安装并启动 `tracesphere-vm-agent.service`；
- 事件追加写入 `/opt/tracesphere/evidence/vm-agent.log`。

编辑 `/etc/tracesphere/agent.env`：

```bash
VMAGENT_PLATFORM_URL=http://<PLATFORM_IP>:8000
VMAGENT_VM_UUID=<VM_UUID>
VMAGENT_TOKEN=<API_TOKEN>
VMAGENT_REPORT_PROCESS=0
# 可选：自定义 cgroup
# VMAGENT_CGROUP=/sys/fs/cgroup/system.slice/docker-<container-id>.scope
# 可选：spool 目录
# VMAGENT_SPOOL_DIR=/var/lib/tracesphere/vm-agent/spool
```

**重要**：`VMAGENT_PLATFORM_URL` 只写到主机和端口，不要带 `/api/v1`；vm-agent 会自行拼接 `/api/v1/events`。带路径会变成 `/api/v1/api/v1/events`。

重启并验证：

```bash
sudo systemctl restart tracesphere-vm-agent
systemctl status tracesphere-vm-agent --no-pager
sudo journalctl -u tracesphere-vm-agent -n 30 --no-pager
sudo tail -n 5 /opt/tracesphere/evidence/vm-agent.log
```

日志中应出现：

```text
reporter enabled: http://<PLATFORM_IP>:8000/api/v1/events (spool=...)
vm-agent started: eBPF probes attached (...)
```

或降级模式：

```text
WARN 部分 eBPF 探针不可用：...
vm-agent started in DEGRADED mode: PSI/cgroup metrics only
```

### 7.6 验证平台入库


| 项 | 建议 |

| RCA | 配置 `TRACESPHERE_RCA_TOKEN`；Console 通过 `?token=` 注入 |
| ZSvirt | 只使用一个账号做只读查询；只读由代码不调用写接口保证，不依赖账号权限 |
| 凭据 | `/etc/tracesphere/*.env` 权限 600；不写入仓库与日志 |
| 工作负载 | 控制面默认回环；`PROM_BIND` 只在平台节点可达的网络中暴露，并用防火墙限制来源 |
| 数据面 | 平台 ingest 字段白名单；不上传问题 / 回答 / 工具结果正文 |
| 传输 | 跨主机部署建议在 platform / RCA 前加 TLS 反向代理；ZSvirt 自签证书时 `verify_tls=false` 仅限内网 |

## 11. 故障排查

| 现象 | 可能原因 | 处理 |
|---|---|---|
| platform 启动即退出，日志 `拒绝启动：host=0.0.0.0 为非回环绑定但未配置 TRACESPHERE_API_TOKEN` | 未配 Token | 写入 `/etc/tracesphere/platform.env` 的 `TRACESPHERE_API_TOKEN`，或仅测试时设 `TRACESPHERE_ALLOW_INSECURE=1` |
| platform health 正常但 `provider` 为 fixture | 未改 `provider=rest` 或环境变量覆盖 | 检查 `platform/config/platform.json` 与 `ZSVIRT_PROVIDER` |
| 启动同步 `ok=False` | ZSvirt 地址 / 口令 / 网络错误 | 用 §5.5 的 curl 手工验证；确认 8080 不是 443；确认密码是 sha512 |
| ZSvirt 登录 401 | 密码字段传了明文 | 改为 `sha512(明文)` 的 hex |
| 同步后 VM 没有 IP | ZSvirt 不记录 `vmNics` IP | 以 Agent 注册的 `ips` 为准，或检查 DHCP / 手工 IP |
| Console 打不开 / 空白 | RCA 未启动、`console/dist` 不存在、构建模式错误 | 检查 `systemctl status tracesphere-rca`、`ls console/dist`、`VITE_DATA_SOURCE` |
| Console 页面显示「无法连接诊断服务」 | 反向代理 / 端口 / Token | 检查 8010、`VITE_RCA_BASE_URL`、`TRACESPHERE_RCA_TOKEN`；api 模式不会静默降级 |
| 页面 401 | RCA Token 未注入 | 访问 `http://<host>:8010/?token=<RCA_TOKEN>` |
| 告警列表为空 | 无关联簇、时间窗过窄、数据源未就绪 | 放宽时间窗；检查 `/api/v1/health` 的 `sources`；确认场景已注入 |
| 诊断无结果 | 窗口内无证据、数据源被禁用、锚点错误 | 检查 `sources.evidence_count`；确认 `correlation_id` / `resource_id`；查看 `sources.notes` |
| vm-agent 无事件 | `VMAGENT_PLATFORM_URL` 为空、Token 不一致、网络不通 | 查看 `journalctl`；确认 URL 不带 `/api/v1`；确认平台 401 日志；spool 目录是否堆积 |
| vm-agent 进入降级模式 | 非 root、memlock 限制、缺 BTF / tracefs | 以 root 运行，或按单元文件注释配置 `CAP_BPF + CAP_PERFMON`；确认内核支持 |
| 容器指标缺失 | cgroup v2 路径不匹配、容器未运行 | 检查 `/sys/fs/cgroup`；用 `VMAGENT_CGROUP` 指定容器 scope |
| Prometheus 目标 down | 容器未启动、端口绑定错误 | `docker compose ps`；确认 `PROM_BIND`；`curl http://<VM_IP>:9090/-/ready` |
| RCA 读不到 Prometheus | `TRACESPHERE_PROMETHEUS_URL` 指向 127.0.0.1 | 改为 `http://<VM_IP>:9090`，并设置 `PROM_BIND=<VM_IP>` |
| Mock GPU 无数据 | 平台未启用 `mock_gpu`、VM UUID 不匹配、Token 错误 | 检查 `TRACESPHERE_MOCK_GPU*`、`TRACESPHERE_VM_UUID`、`PLATFORM_TOKEN` |
| 事件时间对不上 | 节点时钟不同步 | 启用 NTP/chrony；检查 ZSvirt 时钟 |
| 端口被占用 | 旧 nohup 进程 / 其他服务 | `ss -lntp \| grep -E '8000\|8010'`；`install-services.sh` 会停旧进程 |
| 系统盘不足 | 日志 / 模型 / 数据库增长 | 清理 `vm-agent.log`、归档 evidence、扩容磁盘 |
